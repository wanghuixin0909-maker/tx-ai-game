# Neon Echo 改版方案 PRD

## 1. 项目定位

### 1.1 当前产品定位

Neon Echo 目前已经具备以下优势：

- 赛博审问题材明确，首屏气质很统一
- 人物设定、案件背景、UI 氛围已经立住
- “聊天 + 线索档案 + 最终指控”的基本框架完整

当前短板也很明确：

- 玩家在“看剧情”和“玩推理”之间，更多是在看，而不是在破案
- 自由输入虽然有沉浸感，但缺少稳定反馈和节奏控制
- 线索解锁、信任度、阶段推进还不够像真正的系统
- 最终指控更像答案校验，不像证据推理的结果
- 首轮失败兜底不足，线上一旦后端波动，体验会直接断裂

### 1.2 改版目标

把产品从“会聊天的案件展示页”升级成“有明确推进感的 AI 推理游戏”。

核心目标：

- 让玩家每 2 到 3 次操作就获得一次清晰反馈
- 让 NPC 互动从“信息输出”变成“可博弈”
- 让线索从“收集列表”变成“推理链”
- 让结局从“猜凶手”变成“提交论证”

---

## 2. 用户体验目标

### 2.1 玩家进入 30 秒内要感知到的东西

- 我是谁：独立调查员
- 我要做什么：问出真相，锁定凶手
- 我该先做什么：追一个明确问题
- 我每一步会得到什么：证词、怀疑、线索、对质机会

### 2.2 玩家 5 分钟内要体验到的爽点

- 问出第一条有效线索
- 第一次用证据反压 NPC
- 明显感觉到某人开始露出破绽
- 档案面板出现“证据链正在成形”的反馈

### 2.3 玩家完整一局后要留下的记忆点

- “这个人跟我斗智斗勇，不是纯喂答案”
- “我真的是靠整理证据找出真凶”
- “我想再玩一局，看看别的追问顺序会不会触发不同内容”

---

## 3. 核心问题诊断

基于当前线上表现和本地实现，主要问题有五类。

### 3.1 玩法反馈偏弱

- 当前主循环是 `输入问题 -> NPC 回复 -> 有时解锁线索`
- 玩家缺少“我问对了 / 我逼中了 / 我推进了案情”的强反馈
- 线索获得更多像轮次奖励，而不是推理成果

### 3.2 系统感不够强

- `trustLevel` 有展示，但尚未成为玩家能感知并利用的真实机制
- NPC 状态没有明显随玩家策略变化
- 证词没有“真假层次”和“可验证状态”

### 3.3 自由输入门槛高

- 会提问的玩家会觉得有趣
- 不会提问的玩家容易卡住，不知道下一步该问什么
- 如果问题没命中后端逻辑，体验容易空转

### 3.4 档案面板偏静态

- 更像世界观说明书
- 缺少“正在侦破中”的动态张力
- 没有把矛盾点、时间线、证据链、嫌疑变化组织成推理工具

### 3.5 结局论证感不足

- 当前主要是校验必须线索后允许指控
- 玩家不需要真正说明“为什么是她”
- 正确结局更像按钮触发，而不是推理收束

---

## 4. 改版后的核心玩法

### 4.1 新核心循环

建议改成下面这套 6 步闭环：

1. 选择调查方向
2. 进行追问或施压
3. 获得证词、怀疑点或半线索
4. 去其他对象处交叉验证
5. 用证据发起对质，升级为已证实线索
6. 拼出作案链，提交最终指控

这套循环的重点不是“问到答案”，而是“问出可验证信息，再拿它打别人”。

### 4.2 单次操作的反馈类型

每次操作至少要落到下面四类反馈之一：

- 信息推进：新证词 / 新背景 / 新矛盾
- 状态变化：NPC 更信任 / 更戒备 / 开始失控
- 证据推进：传闻升级为可疑，或可疑升级为已证实
- 结构推进：解锁新调查方向 / 新对质动作 / 最终指控资格

### 4.3 关键体验原则

- 玩家不是在“刷文本”，而是在“撬开防线”
- 证据必须可以互相印证
- 一条信息最好能在别处产生作用
- 每个 NPC 都要有自己的玩法价值，而不是只负责分发不同文案

## 5. 系统设计

### 5.1 提问系统

保留自由输入，但增加引导层，采用双轨制。

#### 模式 A：自由提问

- 适合沉浸型玩家
- 保留 AI 对话的开放感

#### 模式 B：推荐追问

每轮在输入框上方给出 3 个推荐动作，例如：

- 追问 Nova 的离岗时间线
- 要求 Echo-7 解释热成像缺口
- 用门禁异常记录试探 Shade

设计目的：

- 给新手明确入口
- 给系统更可控的反馈节奏
- 降低“我不知道该问什么”的流失

### 5.2 NPC 状态系统

把当前的 `status + trustLevel` 升级为真实可玩的系统。

建议至少保留 3 个维度：

- 信任度：影响对方愿不愿意补充背景信息
- 戒备度：影响对方是否回避、转移、说谎
- 崩溃度：影响对方在被证据压制后是否失控或露出破绽

#### 示例规则

- 友好、专业型问题：信任度上升
- 连续施压但无证据：戒备度上升
- 关键证据对质成功：崩溃度上升
- 崩溃度达到阈值：触发特殊证词

### 5.3 线索系统

把线索从当前的“解锁/未解锁”改成三级状态：

- 传闻
- 可疑
- 已证实

#### 状态说明

- 传闻：来自单人口供，不可直接用于结案
- 可疑：至少两处信息相互指向，但仍有不确定性
- 已证实：被日志、物证或多方证词完成闭环

这样玩家会有明显的“我把这条线索坐实了”的爽感。

### 5.4 对质系统

这是本次改版最关键的一层。

玩家不只能问，还能发起“对质动作”。

对质的最小结构：

- 选择目标 NPC
- 选择一条已获得线索或证词
- 选择施压角度

施压角度建议三类：

- 时间线对质
- 权限来源对质
- 动机对质

对质成功后可以触发：

- NPC 状态波动
- 证词升级
- 新调查方向
- 关键剧情片段

### 5.5 推理板系统

把“案件档案”升级成真正的推理工具。

建议拆成四个视图：

- 案件摘要
- 时间线
- 证词冲突
- 证据链

其中“证词冲突”和“证据链”是最重要的。

#### 证词冲突视图

展示：

- 谁说了什么
- 与哪条线索冲突
- 当前冲突是否已核验

#### 证据链视图

展示：

- 作案机会
- 作案手段
- 作案动机
- 掩盖手法

玩家需要逐步把线索挂到这四个槽位上。

### 5.6 最终指控系统

最终指控不再只是“选一个人”。

建议改成三段式提交：

1. 指控对象是谁
2. 她如何作案
3. 关键证据链是什么

提交后系统按以下维度评分：

- 指控对象是否正确
- 作案链是否完整
- 证据链是否闭环
- 是否存在关键矛盾未解决

## 6. 内容设计原则

### 6.1 每个 NPC 的玩法标签

四个 NPC 不能只是在人格上不同，也要在玩法上不同。

#### Nova

- 标签：技术拆解
- 价值：提供门禁、报警、现场机制细节
- 玩法：用精确问题换技术真相

#### Shade

- 标签：交易试探
- 价值：提供黑市流向和利益链
- 玩法：半真半假，需要拿别人的信息换他的松口

#### Echo-7

- 标签：日志恢复
- 价值：提供近似客观的结构化信息
- 玩法：修复缺失片段，补足时间线

#### Iris

- 标签：高压对质
- 价值：最终核心目标
- 玩法：前期难撬，必须带证据逼供

### 6.2 每轮内容的结构

每条高价值回复建议包含三层中的至少两层：

- 表层：直接回应玩家问题
- 中层：补充一个新事实或新矛盾
- 深层：埋下可去别处验证的钩子

这样一段回复才能真正驱动下一步行动。

## 7. 信息架构与页面方案

### 7.1 桌面端结构

建议继续保留三栏，但调整每栏职责。

#### 左栏：对象网络

保留当前形式，但补强为“调查入口”而不只是联系人列表。

新增内容：

- 当前可追问主题标签
- 对该 NPC 的嫌疑趋势
- 是否存在可发起对质
- 最近一次情绪/状态变化提示

#### 中栏：审问与对质主战场

建议拆成四块：

- 顶部：当前对象信息 + 当前目标
- 中部：对话流
- 底部：输入区
- 输入区上方：推荐追问 / 可用对质

新增要点：

- 当前目标必须一句话写清
- 推荐追问作为高频入口
- 当玩家拿到有效证据时，中栏出现明显的同步动画或提示条

#### 右栏：推理板

从“档案展示”升级成“推理工作台”。

推荐标签页：

- 摘要
- 冲突
- 时间线
- 证据链

“摘要”放背景，“冲突/时间线/证据链”承担实际玩法价值。

### 7.2 移动端结构

移动端不适合把太多理解负担丢给用户切页。

建议采用：

- 顶部保留案件概况
- 中部默认停留在审问
- 输入框上方始终保留“当前目标 + 推荐追问”
- 线索解锁后用底部抽屉或半屏卡片弹出

移动端关键点：

- 玩家不需要频繁去档案页确认自己该做什么
- 关键反馈必须在当前视图内完成

## 9. 版本优先级

### 9.1 P0：先把一局玩顺

目标：保证第一次打开就能顺畅玩下去。

范围：

- 后端失败兜底
- 明确当前调查目标
- 推荐追问入口
- 线索解锁反馈强化
- 阶段切换提示

验收标准：

- 玩家第一次打开后，30 秒内知道下一步该做什么
- 后端超时或不可达时，前端不会直接断局
- 玩家不用完全依赖自由输入也能完成一局

### 9.2 P1：把玩法做出推理感

目标：让游戏从“聊天”变成“破案”。

范围：

- 信任度/戒备度真实生效
- 线索三级状态
- 对质系统
- 推理板中的冲突和证据链视图
- 指控改为“对象 + 手法 + 证据链”

验收标准：

- 玩家能明确感知自己的策略影响 NPC 反应
- 至少 50% 的关键线索需要通过交叉验证升级
- 正确结局需要论证，而不是只点对人

### 9.3 P2：增强复玩与传播

目标：让用户愿意再来一局，并愿意分享。

范围：

- 多种审问风格分支
- 多结局评分
- 隐藏线索
- 特殊崩溃台词 / 戏剧性瞬间
- 结案总结页增强

验收标准：

- 玩家完成后能清楚知道自己“差在哪”
- 同一案件有可讨论的不同游玩路径

### 9.4 P3：为多案件扩展做准备

目标：把 Neon Echo 从单案作品升级成案件框架。

范围：

- 案件模板标准化
- NPC 内容配置标准化
- 线索、证词、推理链的数据结构统一
- 多案件入口与存档

## 10. 与现有实现的衔接建议

### 10.1 可复用部分

当前项目里这些基础很好，可以直接沿用：

- 三栏式主界面
- `case-bible.json` 的案件配置思路
- `mockGame.ts` 的 NPC/线索初始化结构
- `CaseFilePanel`、`ChatWindow`、`NpcSidebar` 的组件划分
- 本地存档和阶段字段

### 10.2 需要优先重构的部分

#### 对话推进逻辑

当前更接近：

- 玩家发问
- 后端返回文本
- 前端按轮次挂线索

建议改成：

- 玩家动作
- 后端返回结构化结果
- 前端再渲染为文本和状态变化

建议后端响应结构未来扩展为：

```json
{
  "reply": "文本回复",
  "state_delta": {
    "trust": 3,
    "guard": -1,
    "breakdown": 0
  },
  "unlocked_topics": ["alarm-origin"],
  "clue_updates": [
    {
      "clue_id": "badge-scan",
      "new_status": "suspicious"
    }
  ],
  "suggested_actions": [
    "追问假警报来源",
    "去问 Echo-7 热成像缺口"
  ],
  "contradictions": [
    {
      "target": "iris",
      "reason": "Nova 证词与 Iris 的维护说明冲突"
    }
  ]
}
```

#### 最终指控逻辑

当前主要基于固定线索 ID 判断。

建议改为：

- 检查必要证据是否完整
- 检查玩家是否填对机会/手段/动机链
- 检查是否仍有关键未解决冲突

## 11. 成功指标

如果后续要验证改版是否有效，建议观察这些指标。

### 11.1 体验指标

- 首轮平均有效操作次数
- 首轮完成率
- 首次获得第二条线索的时间
- 首次进入最终指控的比例

### 11.2 玩法指标

- 推荐追问使用率
- 自由输入与推荐追问的使用占比
- 对质系统触发率
- 线索从传闻升级到已证实的平均数量

### 11.3 内容指标

- 哪个 NPC 最常被卡住
- 哪类问题最容易空转
- 哪个阶段流失最高

---

## 12. 推荐落地顺序

如果按最省力又最见效的顺序来做，我建议是：

1. 修线上稳定性和失败兜底
2. 增加当前目标和推荐追问
3. 强化线索解锁反馈与阶段切换
4. 重做档案为冲突/时间线/证据链
5. 上信任度和戒备度真实变化
6. 上对质系统
7. 重做最终指控
8. 最后补多结局、隐藏线索、复玩内容

---

## 13. 一句话版本总结

这次改版的核心不是“让 NPC 更会说”，而是“让玩家更像调查员”。

只要把推荐追问、状态变化、线索升级、证据对质和最终论证这五层补起来，Neon Echo 就会从一个完成度不错的赛博叙事 Demo，变成一个真正有上瘾潜力的 AI 推理游戏。
